## 1. One-Click Host Installer & Hardware Auto-Discovery Harness (`install.sh`)

### 1.1 Objective & Requirements
Create a standalone, idempotent single-command host installer script (`install.sh`) at project root that:
1. Detects host system architecture and hardware specs (CPU cores, total RAM, GPU vendor, GPU model, and dedicated VRAM).
2. Verifies system prerequisites (Python 3.10+, Git, Docker runtime with daemon connectivity, and Zenoh native dependencies).
3. Automatically writes/updates configuration settings (`Node/.env`) with P2P WAN endpoints, host settings, and telemetry security parameters.
4. Provides a CLI entry point (`public-intelligence-node`) and background launch/daemon harness (`scripts/launch_host_node.sh`) integrated with the visual dashboard host control endpoint (`POST /api/v1/node/control`).

### 1.2 Multi-Platform Hardware Discovery Mechanisms

| Hardware / Resource | Target Platform | Primary Discovery Command / Tool | Extraction Strategy | Fallback / Alternative |
|---|---|---|---|---|
| **NVIDIA GPU & VRAM** | Linux / Windows (WSL) / macOS | `nvidia-smi --query-gpu=name,memory.total --format=csv,noheader,nounits` | Parse string CSV: `GPU Name`, VRAM in MiB $\rightarrow$ Bytes conversion (`vram_mb * 1024 * 1024`). | PyTorch CUDA inspect (`torch.cuda.get_device_name(0)`, `torch.cuda.get_device_properties(0).total_memory`). |
| **Apple Silicon GPU & VRAM** | macOS (Darwin) | `sysctl -n hw.memsize` & `system_profiler SPDisplaysDataType` | Detect Apple M1/M2/M3/M4 chip name; extract total system Unified Memory (which functions as VRAM for Metal/MPS). | `machdep.cpu.brand_string` + `vm_stat`. |
| **AMD ROCm GPU & VRAM** | Linux | `rocm-smi --showid --showmeminfo vram` / `rocminfo` | Parse VRAM total bytes and device name string. | `clinfo` / PyTorch ROCm check. |
| **CPU Cores & Threads** | Linux / macOS | `nproc` (Linux) / `sysctl -n hw.ncpu` (macOS) | Count logical CPU threads. | Python `os.cpu_count()`. |
| **System RAM** | Linux / macOS | `/proc/meminfo` (`MemTotal`) / `sysctl -n hw.memsize` | Extract total system memory in bytes. | Python `psutil.virtual_memory().total`. |

### 1.3 Prerequisites Verification Matrix

```bash
# Prerequisites Validation Sequence in install.sh
1. Python 3.10+ check:
   PYTHON_VER=$(python3 -c 'import sys; print(f"{sys.version_info.major}.{sys.version_info.minor}")')
   # Enforce >= 3.10 requirement

2. Git check:
   command -v git >/dev/null 2>&1 || { echo "Error: git is required for runtime sandbox worktrees."; exit 1; }

3. Docker runtime & daemon check:
   command -v docker >/dev/null 2>&1 || { echo "Error: docker binary not found."; exit 1; }
   docker info >/dev/null 2>&1 || { echo "Error: docker daemon is not running or current user lacks permission."; exit 1; }

4. Virtual environment & Zenoh dependencies setup:
   python3 -m venv Node/.venv
   Node/.venv/bin/pip install --upgrade pip setuptools wheel
   Node/.venv/bin/pip install -e Node/
```

### 1.5 CLI Entry Point & Background Daemon Harness

1. **CLI Script Entry Point**:
   Add `[project.scripts]` entry in `Node/pyproject.toml`:
   ```toml
   [project.scripts]
   public-intelligence-node = "node.main:cli_main"
   ```
   In `Node/src/node/main.py`, define `cli_main()` using `uvicorn.run("node.main:app", host=settings.host, port=settings.port)`.

2. **Background Launch Harness (`scripts/launch_host_node.sh`)**:
   Provides options for starting the node in background mode, saving stdout/stderr to `Node/node.log` and saving PID to `Node/node.pid`.

3. **Host Control API Integration**:
   `Node/src/node/api/control.py` already implements:
   - `GET /api/v1/node/telemetry`: retrieves live CPU, RAM, GPU/VRAM, and P2P connection status.
   - `POST /api/v1/node/control`: accepts `{"action": "start"}` or `{"action": "stop"}` to toggle `app.state.runtime`.

## 2. Docker Sandbox Isolation Guarantees & Container Status Logging

### 2.1 Workspace & Runtime Isolation Architecture
File Location: `Node/src/node/core/runtime.py`

```
WorktreeManager
  ├── create_worktree(branch_name)  ──>  creates isolated git worktree at /tmp/node_worktree_<branch_name>
  ├── execute_in_sandbox(branch_name, command, image)
  │     ├── Container Constraints:
  │     │     ├── -v /tmp/node_worktree_<branch_name>:/workspace -w /workspace
  │     │     ├── --memory 512m         (strict memory limit)
  │     │     ├── --network none        (isolated air-gapped network)
  │     │     ├── --user <uid>:<gid>    (non-root user execution)
  │     │     └── timeout=60.0s         (hard execution ceiling)
  │     └── Log Capture:
  │           └── Redirects stdout & stderr to SandboxLogBuffer
  └── cleanup_worktree(branch_name) ──> removes worktree & directory
```

### 2.2 Container Log Ingestion & Real-Time SSE Stream Endpoint
File Location: `Node/src/node/api/control.py`

- `SandboxLogBuffer`: Thread-safe bounded ring buffer storing up to 1000 log entries (`timestamp`, `stream`, `branch`, `message`).
- `GET /api/v1/sandbox/logs`: REST endpoint returning recent log entries JSON array.
- `GET /api/v1/sandbox/logs/stream`: SSE streaming endpoint (`text/event-stream`) pushing real-time container log events to visual dashboard log viewers.

### 2.3 Hardened Security Invariants
1. **Network Air-Gapping**: `--network none` guarantees that untrusted code executed in the container cannot open outbound connections or leak data.
2. **Resource Throttling**: `--memory 512m` prevents rogue container workloads from starving host system memory.
3. **Execution Ceiling**: `asyncio.wait_for(..., timeout=60.0)` automatically triggers `proc.kill()` if a container hangs or loops infinitely.

### 3.2 Key Test Scenarios & Assertion Matrix

| Test Suite Module | Target Component | Verifications & Assertions |
|---|---|---|
| `test_telemetry_e2e` | `TelemetryCollector` $\rightarrow$ `TelemetryEmitter` $\rightarrow$ `ZenohRouter` $\rightarrow$ `NodeRegistry` | - Encrypted payload parsed correctly with pre-shared key.<br>- Tampered HMAC signature rejected.<br>- Timestamp staleness >30s dropped.<br>- `GET /api/v1/node/telemetry` returns non-zero metrics and `wan_connected: true`. |
| `test_openai_sse_e2e` | `POST /v1/chat/completions` (Scheduler) $\rightarrow$ `/infer` (Node) | - Missing JWT returns `401 Unauthorized`.<br>- Exceeded token bucket returns `429 Too Many Requests`.<br>- Non-streaming request returns `ChatCompletionResponse` JSON.<br>- `stream: true` returns SSE event stream ending with `data: [DONE]`. |
| `test_ingress_task_e2e` | `POST /api/v1/tasks/submit` (Scheduler) $\rightarrow$ Worker Runtime | - Matches node capable of hosting model.<br>- Replicates task state across Raft consensus engine.<br>- Computes out-of-band SHA-256 artifact ID `art_<task_id>_<checksum[:12]>`.<br>- Returns 64-character hex transaction hash. |
